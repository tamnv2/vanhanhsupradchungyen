## Reason

Owner has only two physical Newland MT90 devices and requested the next pilot to collect comprehensive evidence for LAN viability: automatic LAN priority/reacquisition, data throughput, realtime propagation across PDA/laptop/PDA, heavy-case behavior, service capacity and related diagnostics.

## Prior physical evidence

Diagnostics from release 0.1.12 established:

- restricted ordinary-user laptop Agent execution works;
- two Newland NLS-MT90 Android 11 devices reached LAN_ACTIVE;
- no manual endpoint was stored in either export;
- health success streaks 73 and 67, failures 0;
- durable queue returned to zero;
- Agent SQLite accepted events and rejected a duplicate deterministically;
- observed captured echo samples were roughly 10–57 ms; Agent session p50/p95/p99 roughly 47/67/90 ms.

This evidence is sufficient to continue feasibility testing but not to claim final PASS.

## Source changes

### Windows Agent

Added `PilotV3.cs` and switched startup to `V3Program`.

New BETA-only APIs/capabilities:

- health start timestamp + LAN priority capability declaration;
- bounded realtime event buffer;
- long-poll realtime receive;
- realtime publish;
- streaming upload test capped at 64 MiB;
- streaming download test capped at 64 MiB;
- realtime/transfer metrics;
- device-safe diagnostic labels;
- discovery request logging;
- local-loopback-only LoadGen launch from Test Center;
- Test Center UI with realtime display latency and 10/25/50/100 logical-client buttons.

### Android

Added `MainActivityV3` and switched launcher to V3.

New behavior:

- application-level LAN priority monitor while APK process is alive;
- aggressive reacquisition attempts when not LAN_ACTIVE;
- UDP/cache source evidence where observable;
- Agent-start -> LAN_ACTIVE delay estimate;
- realtime receive loop with latency and sequence-gap tracking;
- realtime publish single and 200 x 2 KB heavy mode;
- 1 MB / 25 MB transfer buttons;
- FULL suite: 100 echo + upload/download 1/10/25 MB + realtime heavy;
- FULL diagnostics export merging V3 test history with base diagnostic history.

### Test policy

Created `docs/lan/LAN_PILOT_002_COMPREHENSIVE_TEST.md`.

Recorded D-029: exactly two physical MT90 are the present RF/Wi-Fi evidence ceiling; synthetic load supplements software-capacity evidence but cannot prove RF behavior above two physical devices.

## Known limitations to measure, not hide

- LAN priority is application transport selection, not an Android OS route override.
- If Android suspends/kills the process during screen-off/background, reacquisition may stop until process resumes; 0.2 explicitly tests this to decide whether a foreground LAN monitor is required.
- RF/Wi-Fi behavior above two real PDA remains unproven.
- Final production LAN release still requires no-admin staged Agent self-update + health rollback verification.

## Rollback
